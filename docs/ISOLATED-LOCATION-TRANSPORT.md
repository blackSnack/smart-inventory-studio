# Isolated migration transport (#10 #17 #28)
This module has no PWA integration and only accepts an explicit injected fetch for an HTTPS .test fixture. It cannot be configured with the user's NAS. Public schema references: https://docs.inventree.org/en/latest/api/schema/stock/ and https://docs.inventree.org/en/latest/api/schema/general/. The fixture metadata model key is explicit, not assumed to match the actual server.
The fixture checks schema declaration, re-reads existing location IDs and parents, rejects sibling name conflicts, PATCHes only name, checks metadata and expected leaf references before PATCH, and reads back after mutation. A lost response is reconciled through the journal without replay. Unrelated metadata is preserved. No stock operations, no DELETE/POST, and no live credentials.
Runtime actual schema, correct metadata model identifier, auth/permissions, PATCH semantics and concurrent writers must be validated in #23. GET precondition then PATCH is not atomic compare-and-set; do not enable production writes until the concurrency boundary is verified. Stock references and quantities must be checked separately in the isolated instance.

The regression now generates its approved operations directly from the actual legacy migration planner. The fixture validates the full cabinet metadata and coverage of planned leaf IDs before writing or verifying, and rejects duplicate target names during rename readback. This proves the software seam, not a production API contract.
