# Versioned preview releases
A release PR must bump web/package.json and the root version fields in web/package-lock.json, and prepend a matching Chinese changelog entry in web/release-history.json. Include actual changes and limitations. Merge through the normal CI gates. Main builds that reuse an already published version do not replace the published app; explicitly bump the version for each delivery. Release names use vMAJOR.MINOR.PATCH; pre-production versions are GitHub prereleases.
The Pages workflow validates the exact main commit, builds once, packages the React static app, deploys the same artifact to /react-preview/, verifies the public version manifest, then publishes the GitHub Release with a zip and SHA256. A published version is immutable; do not overwrite or retag. Retry a failed release workflow at the same commit, not a different one. Existing HTML demo remains at the root.
The running app checks the same-origin version.json every 60 seconds when visible, immediately at launch, on returning to foreground and when network connectivity resumes. Browsers can throttle/suspend background timers. The manifest is network-only, not in the service-worker cache; version comparison is numeric. Changes across skipped versions come from the versioned history. The user must confirm reload after saving drafts; no automatic reload. Waiting worker must report the exact target version and commit. IndexedDB journals and unrelated caches are retained. The currently published app is a preview; no live inventory writes.
Acceptance: two actual builds in a project subpath, current version, 60s discovery, cumulative notes, no automatic reload, explicit activation/reload, new running version and offline shell. Physical-device behavior and real backend acceptance are deferred.
