# OPS-01 software acceptance and live handoff (#28)
The journal is the authority for approved plans, not a transport retry queue. The original issue's software exit criteria are mapped below. No production service or data is touched.
- State machine, exact approved snapshot, per-instance operation ID: operation-journal.ts, approved-snapshot.ts, inventory-contract.ts, indexeddb-journal.ts. Operation IDs cannot be reused even across stopped or completed plans in an instance.
- Persist sent before dispatch, checkpoint and evidence, readback only: operation-journal.ts. IndexedDB atomic CAS and admission prevent two tabs dispatching a plan twice.
- Non-idempotent fixture requests: optional IndexedDbFixtureEvidence reserves each operation ID before request and records only a validated response acknowledgement, scoped to fixture base and instance. Pass the same explicit instanceId as the journal. Reopen using the same database, canonical base and instance; never infer an acknowledgement from a matching quantity or name. Fresh readback still required. Evidence-store write failure, response loss before durable acknowledgement or uncertain mutation remains unknown.
- Conflict: blocked/unknown prevents dispatch of current and later steps. Read-only reconciliation is allowed after write revocation. Do not retry an uncertain operation. If verified by fresh evidence, the reviewed never-sent suffix may be stopped and replanned with new IDs and approval. If unresolved, preserve the block and obtain external evidence; do not mark it verified or clear it manually just to admit new work.
- Tests: journal-browser.py executes real Chromium IndexedDB cross-plan identity checks, cross-tab reservations, reload after durable response but before journal checkpoint, fresh readback conflict, verified prefix, stop and no replay. Existing tests cover lost response before acknowledgement, partial success, stale approvals and isolated router behavior.
Real acceptance remains #10/#23: verify actual 1.7.4 schema, write permissions, response and audit correlation in an isolated instance; validate native operation evidence and conflicts privately. Browser persistence is local, not a server transaction, and no server-side durable attribution or production write capability is claimed. No protocol kinds, existing journal schema or production authorization gates changed.
