# Native existing-Part receipt candidate (#23)

Read-only business seam: InvenTreeReceiptCandidateReader uses the same schema declaration probe and read-only pagination as the existing app. An explicit selected Part and bounded allocation list are checked against the exact Part detail, actual location tree, each leaf's raw StockItem records (ID, Part, location, decimal quantity, batch, serial, status), and direct occupancy. Repeated, mixed or missing records, non-leaf destinations, unsupported trackable/virtual/inactive Parts, and changes between two passes reject the candidate. A recheck compares the entire selected snapshot, including identity and hierarchy. A zero-quantity record of a different Part is conservatively rejected to match the existing isolated receipt transport.

The returned object is not an ApprovedPlan: it has no approval or operation IDs, no write capability, baselineComplete=false and explicit review flags. It is a stable visible projection, not a transaction, proof of full visibility, capacity or physical identity. Callers must verify the instance namespace, visibility and actual physical placement. The read-only UI is not modified here; the existing fixture-only transport remains explicitly restricted to .test. No real API write or production authorization is enabled.

The same stock normalization is shared with the existing isolated write adapter. A synthetic end-to-end regression feeds this candidate into the existing receipt planner only after explicit fixture review, binds exact baselines and executes the journal against an injected service. It verifies multi-leaf writes, preservation of earlier stock, confirmed prefix, lost acknowledgement and no blind replay. This does not certify real integration or server attribution. Actual #23 disposable-instance acceptance and production approval remain separate.
