# Browser isolated native acceptance (#23)

The existing static PWA now has a distinct isolated acceptance path. It does not grant production write permission. Production NAS addresses remain read-only. This is intentionally restricted to an explicitly authorized disposable InvenTree 1.7.4/API 570 instance on literal loopback with explicit port; never use a tunnel/proxy to production. Browser CORS, local-network permission, TLS and actual native permissions still require local verification. No extra service or host setup is introduced.

1. In the live inventory settings, enter the URL and Token. Select the disposable-instance acceptance checkbox, then test/connect. If native version/auth/schema checks fail, the connection remains read-only. Credentials stay in memory. Confirm the test instance and actual visibility/permissions independently; OpenAPI declarations are not write authorization.
2. Home/parts: search the actual Part, use the existing detail entry to append stock, or choose new independent Partial Part/batch creation. Photo/manual drafts can open the same Part creation form. Existing-Part allocation supports multiple leaf locations with exact total validation; each allocation is reviewed and executed separately. New Part creation can queue its dependent receipt allocations. Every allocation uses only the verified creation acknowledgement ID, checks the expected IPN, and requires fresh independent review. Manufacturer/supplier identity creation is not supported. The existing AI reviewed enrichment plan can now be sent into the native queue, preserving approved parameter baseline. Link and parameter operations also have manual evidence forms.
3. Storage: create structural/leaf locations, rename a leaf, choose a native StockItem and transfer whole or fractional quantity, bind a cabinet to existing leaves and expand a managed layout. Bind every compartment and preserve prior leaf references. Physical movement and capacity are operator decisions. Destructive deletion/reparenting, arbitrary physical split/merge topology changes are not enabled. Category/template creation and direct catalog association are available under the isolated business acceptance form.
4. Review the exact preparation and current native evidence, check all confirmation boxes, execute one operation, observe independent readback. The operation admission and durable reservation are atomic across tabs on the same origin. Uncertain writes remain readback-only; a never-reserved row may be stopped explicitly. Reconnect using the same address/account/browser profile to recover. Never clear browser data or rename an unresolved operation to retry. The operation queue is persisted before preparation. Reopening resumes its unsent suffix; only verified entries can be advanced automatically. An unknown or blocked sent operation never authorizes replay. Unsent items may be explicitly stopped without erasing the journal. A verified row is not server audit attribution; collect that evidence locally.
5. Keep all private local journal data off GitHub. Verify actual service audit, backup/restore, visibility and production authorization separately. No production writes, catalog freeze, actual browser/device connectivity or final native acceptance are asserted by this change.

## Production activation gate
The same business workflow can target a configured HTTPS production origin only after the bundled shared catalog has been approved as v1.0 (`approved_for_production`), and the operator imports a private deployment authorization record from local acceptance. This is not permission inferred from OpenAPI. The record requires exact target base, actor, schema SHA-256, canonical catalog hash/version, environment, backup/restore, catalog freeze, isolated acceptance, actual permissions/visibility and references/audit evidence hashes, a separately approved authorization ID, and explicit production authorization. The user must verify the actual underlying evidence; hashes are references, not signatures or proof of truth. No production authorization is created by the repository or by a connectivity check. The current draft catalog disables the production UI. See PRODUCTION-NATIVE-AUTHORIZATION.md. All operations still require per-operation review and approval; switching credentials or schema invalidates prior preparations. Production and disposable journals are separate. No real production write performed.
