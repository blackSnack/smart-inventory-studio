# Browser isolated native acceptance (#23)

The existing static PWA now has a distinct isolated acceptance path. It does not grant production write permission. Production NAS addresses remain read-only. This is intentionally restricted to an explicitly authorized disposable InvenTree 1.7.4/API 570 instance on literal loopback with explicit port; never use a tunnel/proxy to production. Browser CORS, local-network permission, TLS and actual native permissions still require local verification. No extra service or host setup is introduced.

1. In the live inventory settings, enter the URL and Token. Select the disposable-instance acceptance checkbox, then test/connect. If native version/auth/schema checks fail, the connection remains read-only. Credentials stay in memory. Confirm the test instance and actual visibility/permissions independently; OpenAPI declarations are not write authorization.
2. Home/parts: search the actual Part, use the existing detail entry to append stock, or choose new independent Partial Part/batch creation. Photo/manual drafts can open the same Part creation form. Existing-Part allocation supports multiple leaf locations with exact total validation; each allocation is reviewed and executed separately. New Part creation and receipt are separate reviewed steps (search the created Part before receiving). Manufacturer/supplier identity creation is not supported. The existing AI reviewed enrichment plan can now be sent into the native queue, preserving approved parameter baseline. Link and parameter operations also have manual evidence forms.
3. Storage: create structural/leaf locations, rename a leaf, choose a native StockItem and transfer whole or fractional quantity, bind a cabinet to existing leaves and expand a managed layout. Bind every compartment and preserve prior leaf references. Physical movement and capacity are operator decisions. Destructive deletion/reparenting, arbitrary physical split/merge topology changes are not enabled. Category/template creation and direct catalog association are available under the isolated business acceptance form.
4. Review the exact preparation and current native evidence, check all confirmation boxes, execute one operation, observe independent readback. The operation admission and durable reservation are atomic across tabs on the same origin. Uncertain writes remain readback-only; a never-reserved row may be stopped explicitly. Reconnect using the same address/account/browser profile to recover. Never clear browser data or rename an unresolved operation to retry. Unsent queue suffixes are in-memory drafts; after refresh, independently replan them. Verified prefix is retained locally. A verified row is not server audit attribution; collect that evidence locally.
5. Keep all private local journal data off GitHub. Verify actual service audit, backup/restore, visibility and production authorization separately. No production writes, catalog freeze, actual browser/device connectivity or final native acceptance are asserted by this change.
